一篇文章只能住进一个抽屉吗？——重新拆开 Category、Kind 与 Tags
2026-08-23
行思集·随想
/
写作
/
内容分类

NOTE

AI 协作说明： 本文源于我对现有博客分类的困惑。我提供问题、文章案例与原有分类逻辑，Korewaxnne（基于 Claude 的 AI 助手）协助盘点现状、拆分概念并整理成文，最终结构由我们共同讨论确定。

在写完 什么叫做从她的长相就能看出来是病娇？ 后，我给它加了一个新的 Category：

胡思乱想。

这篇文章从 AI 漫剧里一个很符合我想象的病娇角色写起，中间却花了大量篇幅展示 SeedVR2 的图像超分效果。我既没有认真分析那部剧，也没有把超分过程整理成教程，最后甚至承认自己其实说不清“为什么从长相就能看出来是病娇”。

放进「观后」似乎不够像观后，放进「教程」又没有可供复现的步骤，放进「思考」好像也没形成多么完整的结论。于是我临时造出了「胡思乱想」这个抽屉。

文章是顺利放进去了，分类却更乱了。

文章并没有那么纯

这不是第一次遇到这种问题。

OBS和VTube Studio的联合使用：Be a Vtuber 顶着 Vtuber 的标题，正文却是一篇明确的软件配置教程。从 NEKOPARA 的一篇评测开始 由一条 Steam 评测触发，最终谈的却是生命、改变与人生意义。云服务商跑路后：再次审视个人博客的形态与值得被记录的东西 从服务器跑路和存档丢失写起，最后抵达的是“什么值得被记录”。

还有一些文章，一半是技术实践，一半是对自己的追问。比如 大模型时代：我的能力究竟是什么？：AI Coding 是它的背景，真正想回答的却是失去编码能力之后，我还能把什么称为自己的能力。

如果分类只看文章提到了什么，这些文章可以同时属于技术、书影剧游和哲学思考；如果只允许选择一个，就总会觉得另一部分被丢掉了。

但问题也许不在于文章“不纯”。个人博客本来就不是图书馆的标准书目：一次体验可以引出技术尝试，技术尝试也可能转回对自己的认识。真正的问题是，我一直让同一个 category 回答几个不同的问题。

一个字段承担了三份工作

目前博客里的主要分类是：

  • 资源
  • 观后
  • 教程
  • 思考
  • 边写边学

它们看上去都是分类，实际上并不处于同一个层面。

「教程」和「观后」更像文体，描述读者将以什么方式读这篇文章；「资源」描述文章提供的功能；「边写边学」描述创作过程；「思考」则描述内容试图达到的深度。与此同时，我又希望 Category 能告诉读者文章在谈技术、作品，还是生活与哲学。

换句话说，一个字段同时耦合了三个问题：

  1. 文章主要在写什么？
  2. 文章以什么方式写？
  3. 文章具体涉及哪些对象与概念？

只要三个问题的答案恰好一致，旧结构就显得很好用。一篇 OBS 配置指南是「教程」，一篇电影观后感是「观后」，看上去没有任何问题。

但当一篇文章由游戏出发思考生命，或者为了喜欢的角色研究图像超分时，三个答案便开始分叉。继续增加「胡思乱想」这样的分类，只是在为每一种混合比例制造新的抽屉。

《云服务商》里的分类并没有失去价值

我曾在 云服务商跑路后：再次审视个人博客的形态与值得被记录的东西 中，把值得记录的内容分为资源、观后、教程、思考与边写边学。

那套划分对我仍然很重要。

它讨论的并不是“世界上有哪些题材”，而是“我为什么要写下这些东西”：资源可以帮助别人，观后可以成为回忆展柜和同类诱捕器，教程保存可复现的流程，思考让我得到暂时自洽的结论，边写边学则留下探索、验证和修正的过程。

它的价值恰恰在这里。它允许一篇文章不必先成为标准答案才值得存在，也避免因为早期理解可能幼稚或错误，就干脆停止记录。

所以新的分类不应该取代这套逻辑，而应该把它放回更合适的位置：它描述的是文章的写法与阅读承诺，而不是文章的主题归宿。

把三个问题重新拆开

我目前设想的新结构由 category、kind 和 tags 三部分组成。它们不是三套并列的标签，而是职责不同的三条轴。

Category：文章最终抵达哪里

category 只回答一个问题：这篇文章主要被收进哪一部文集？

每篇文章只能有一个 Category。内部使用稳定、不随展示文案变化的 key；页面上再显示更符合博客气质的名称。

「格物集」「岁时集」这类带有文集感的命名方式，受到了 Soulter 的博客 启发。这里借用的是把普通栏目重新写成个人文集的思路；具体名称和边界，仍然按照本站已有文章重新确定。

内部值 中文显示 收录内容
technology 格物集 技术、工具、工程实践与原理探索
culture 游艺集 书、电影、电视剧、动画、漫画与游戏
thought 行思集 哲学、自我审视、社会观察与人生问题
life 岁时集 个人经历、旅行、阶段总结与生活记录

选择 Category 时，不按照文章由什么触发，而按照它最终抵达的地方。

由游戏触发的人生思考仍然属于行思集；以 Vtuber 为使用场景的软件配置教程仍然属于格物集；一篇旅行中的哲思，如果主体是在保存那段旅程，也仍然可以住进岁时集。

Category 只负责给读者一扇主要入口，不需要穷尽文章的全部含义。

Kind：这篇文章怎么写

kind 回答的是：读者接下来会读到什么形式的内容？

内部值 中文显示 阅读承诺
tutorial 教程 给出可以重复执行的操作步骤
review 观后 围绕某部作品记录体验、评价与感受
reflection 随想 从某件事出发，形成相对完整的思考或结论
learning-note 边学边记 保留探索、验证与修正的过程
resource 资源 提供渠道、工具或资料集合
note 随记 保存一个片段、发现、展示或暂未展开的体验

这里新增了「随记」，用来容纳那些值得保存、却不必假装已经形成完整论述的内容。

「随想」与「随记」的区别不在篇幅，而在文章有没有试图得出一个观点：随想最终想说明什么，随记则可以只是把某次体验和发现留住。最新的病娇与 SeedVR2 文章更接近后者。

Kind 同样是单值枚举。不能因为偶然写出一种新口味，就立刻添加「胡思乱想」「开箱」「经验」等新值；只有当某种写法反复出现，并且现有类型确实无法描述时，才值得扩充。

Tags：具体谈到了什么

tags 只回答：这篇文章涉及哪些具体对象、技术和概念？

适合作为 Tag 的是：

  • SeedVR2
  • 图像超分
  • NEKOPARA
  • Agent
  • 存在主义
  • VTube Studio

「教程」「观后」「思考」「边写边学」「技术」则不再适合作为 Tag。它们描述的是文章结构或主要归属，已经分别由 Kind 和 Category 承担。

Tags 保持多值和开放，但尽量使用可以独立成为检索对象的名词。中英文文章共用同一套 Tag：技术和产品沿用官方名称，作品、人物与概念则保留原名或站内最通行的名称，不再为了翻译制造两份彼此断开的索引。这样 Tags 不会退化成另一个 Category，也不会和 Kind 重复表达同一件事。

其他字段也各自留在自己的位置

博客已经存在一些比 Tags 更具体的组织方式，也不应该被新结构吞掉：

  • shelf 表示作品媒介，例如书籍、电影、动漫或游戏；
  • subCategory 表示媒介内部的细分，例如 galgame；
  • series 表示作者主动组织起来的一组连续文章，例如博客、LLM 或阅读。

它们与 Category、Kind、Tags 的关系可以概括为：

字段 回答的问题
category 文章最终归入哪个内容领域？
kind 文章采用什么写法？
tags 文章具体谈到什么？
shelf / subCategory 文章对应哪种作品媒介？
series 文章属于哪条持续展开的写作线索？

每个字段只回答一种问题，才能避免过一段时间后再次粘成一团。

几篇混合文章会怎样归类

新结构并不消灭混合文章，只是让混合的不同部分各自有位置。

病娇角色与 SeedVR2

它的出发点和主体体验来自漫剧，文章形式则是一组图片展示与即时感受，所以是「游艺集 · 随记」。SeedVR2 和图像超分仍然可以通过 Tags 被找到。

Be a Vtuber

Vtuber 是使用场景，文章实际承诺的是一套软件配置步骤，所以是「格物集 · 教程」。

从 NEKOPARA 的一篇评测开始

游戏是触发物，文章最终抵达的是对生命与改变的思考，所以是「行思集 · 随想」。shelf 和 Tags 会保留它与 NEKOPARA、galgame 的联系。

云服务商跑路之后

技术事故是起因，文章真正追问的是博客形态和记录的意义，因此同样属于「行思集 · 随想」。

拆开以后得到了什么

最直接的好处是，我不必再为每篇“不够纯”的文章发明一个 Category。

对读者来说，「格物集 · 教程」和「游艺集 · 随记」同时给出了内容方向与阅读预期，比一个孤立的「思考」或一串没有层级的标签更明确。对归档与统计来说，内容领域和写法也可以分别观察，而不是把技术教程、作品观后和个人反思混在同一张分类图里。

稳定的内部 key 还能把数据与展示文案解耦。中文可以显示「格物集」，英文可以使用另一套自然的名称，URL 和文章元数据却不必跟着每次改名一起变化。

更重要的是，它承认了个人博客里的文章本来就会混合。分类的目的不是替文章确定唯一身份，而是帮助读者找到一条合适的进入路径。

先把原则写下来

这篇文章描述的还是一份准备落地的结构，而不是当前站点已经完成的功能。

接下来还需要单独处理 schema、页面展示、归档筛选、旧链接兼容与历史文章迁移。Category 和 Kind 在卡片及文章页上怎样呈现，也值得作为一次具体的设计问题继续讨论。英文版则会在中文表达敲定后，以本文为基准同步发布。

至于这次临时出现的「胡思乱想」，我会先把它收回现有的「思考」。它不是一个应该长期存在的新分类，更像一张提醒我重新整理抽屉的便签。
